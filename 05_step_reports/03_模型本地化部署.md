# 步骤 03 · 模型本地化部署

> 一句话：把 19 个模型的**完整开源代码 + 完整权重**全部落到本机，用**零拷贝联接**组织，做到「代码与权重都只有一份物理副本」。  
> 对应计划阶段：**阶段 0（T0.3~T0.6）** ｜ 交付汇报日期：2026-09-28  
> 专项取证见 [`附录_模型本地化验证报告.md`](附录_模型本地化验证报告.md)。

---

## 1. 这一步要什么

| 要解决的问题                       | 验收标准                                  |
| ---------------------------- | ------------------------------------- |
| 代码全部在本机、且是**完整源码**（非浅克隆、非镜像） | 每个仓库 `is-shallow == false`，commits 真实 |
| 权重全部在本机、**单一物理落点**           | `_weights/` 按 inode 去重后无内部重复          |
| 模型目录零冗余                      | `code/` 为目录联接，不产生代码副本                 |
| 可机器核验                        | 有 PASS/FAIL 核验脚本                      |

---

## 2. 做了什么

### 2.1 代码：14 个仓库落 `_third_party/`

一次性 clone 全部第三方仓库到 `01_models/_third_party/`，覆盖板 1 与板 2 全部模型的依赖：

`BS-RoFormer · bsrnn · Conv-TasNet · demucs · denoiser · DNN-based_source_separation · Dual-Path-RNN-Pytorch · mdx-net · mdx-net-submission（+leaderboard_A/B）· Music-Source-Separation-Training · open-unmix-pytorch · sigsep-mus-oracle`

### 2.2 权重：集中到 `_weights/`（唯一落点）

51 个权重/配置文件统一到 `01_models/_weights/`，按模型分目录（`BS-RoFormer/`、`BSRNN/`、`denoiser/`、`MDX-Net/`、`mel_roformer_*/` 等）。

### 2.3 零拷贝组织：26 个 `code/` 联接

`01_models/<板块>/<模型>/` 内**只放 `code/`** —— 指向 `_third_party/<repo>` 的**目录联接（junction）**：

```
01_models/separation/Demucs/code/demucs  ──联接──→  01_models/_third_party/demucs
```

| 联接方式                           | 用在                         | 为什么                                      |
| ------------------------------ | -------------------------- | ---------------------------------------- |
| **目录联接**（junction，`mklink /J`） | `code/<repo>`、部分多目录权重      | 目录级、**不需管理员权限**（符号链接 `mklink /D` 需要，故不用） |
| **硬链接**（`os.link`）             | 单文件权重（如 Demucs/Open-Unmix） | 文件级、同卷，同一份物理数据                           |

### 2.4 补齐三处缺口（这是「完整源码」的关键）

部署前，`_third_party` 里的代码**不完整**，本轮逐个补齐：

| 缺口                          | 证据                                                                           | 处置                                                                                                  |
| --------------------------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| **A. 12 个仓库是 depth=1 浅克隆**  | `git rev-parse --is-shallow-repository` 全 `true`，`rev-list --count HEAD` = 1 | `git fetch --unshallow`（**12/12 成功**）；`_third_party` 743 MB → **2.11 GB**                           |
| **B. `demucs` 根本不是 git 仓库** | 目录有 `.gitignore` 却**没有 `.git`**，无法说出是哪个版本                                    | clone 官方仓库 → 逐文件比对（排除行尾后 **101/101 一致**）→ 替换为 HEAD `e976d93`，版本 `4.1.0a2` **与原目录一致**                |
| **C. Open-Unmix 源码不在项目里**   | `_third_party/` 里没有 open-unmix，代码只在 venv 的 `site-packages/openunmix/`        | clone `sigsep/open-unmix-pytorch` **tag `v1.3.0`**（与 venv 内 `openunmix==1.3.0` 对齐）到 `_third_party/` |

> 附带修正：Demucs 与 Open-Unmix 的权重原先**只存在于 `tools/_scratch/.cache/torch/hub/checkpoints/`**（torch.hub 缓存），  
> 已在 `_weights/Demucs/`、`_weights/open-unmix/` 建**硬链接镜像**（`nlink=3`：缓存 + `_weights/` + 模型目录，同一份物理数据，零占用），  
> 使「`_weights/` 为唯一物理落点」这条约定真正成立。

### 2.5 版本 3 精简：删两个冗余层

经核验证明 `<模型>/weights/`（只是别名，脚本从不读）与 `<模型>/README.md`（内容可由 `model_profile.csv` + 板块索引还原）是**纯冗余** → 删除。  
**删除前先证伪「有独有数据」**：逐个文件核验 inode → **50/50 全部同源，无一独有** → 安全。  
结果：目录层数 **3 层 → 2 层**，语义更清晰（模型卡原文归档到 `tools/_scratch/_archive_model_cards_2026-09-23/`）。

### 2.6 `.gitignore` 必须忽略联接层

补 `01_models/*/*/code/`（+ 兜底 `01_models/*/*/`）—— **否则 git 会把目录联接当普通目录递归进去，把 2 GB 第三方仓库再抄一遍**。

## 5. 结论与坑

- ✅ **本地保存的是全部开源源码**：14/14 完整克隆、remote 指向官方 GitHub、可离线读取；权重全部本地。详见附录。
- 🔴 **坑 1（Windows junction 陷阱）**：`os.readlink()` 返回值带扩展长度前缀 `\\?\`，直接做 `Path.relative_to()` 会**判不中**（`is_dir()` 却为 True）→ 必须先剥前缀再比较。
- 🔴 **坑 2**：`.gitignore` 漏掉 code 联接层 → git 递归抄库，仓库体积翻倍。
- 🔴 **坑 3**：`bsrnn` 完整历史达 **932 MB**（仓库历史含大二进制），是最大单项开销；浅克隆虽省空间但**不可追溯**，不用。
- ✅ **可逆**：删冗余层的操作有清单 `04_reports/00_shared/data/_reclassify_manifest.json`（79 条）。
