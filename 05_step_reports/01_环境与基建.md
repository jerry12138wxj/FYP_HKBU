## 2. 做了什么

### 2.1 解释器与 GPU 环境

- **解释器（唯一）**：`C:\Users\jerry\.workbuddy\binaries\python\envs\fyp_audio\Scripts\python.exe`

- **深度学习栈**：`torch 2.14.0+cu126` / `torchaudio`；CUDA wheel 只从

- **硬件**：RTX 4070 Laptop **8 GiB**（sm_89）。8 GiB 是全程最大的资源约束。

### 2.2 环境铁律（写死，后续所有脚本遵守）

| 铁律 | 原因 |
|---|---|
| 脚本一律 `import paths as _paths; _paths.setup_env()` | 统一环境变量与路径 |
| **每模型一子进程** | 15+ 模型同进程会显存耗尽 |
| `PYTORCH_CUDA_ALLOC_CONF=max_split_size_mb:512` | 抑制碎片 |
| **禁** `expandable_segments:True` | 与 `torch.istft` 冲突（空串→WinError 1114） |
| `print` 全 ASCII | bash 让 stdout 退回 GBK，中文/emoji 必崩 |
| `git config core.longpaths=true` | **必需而非可选**：曾因 Windows 260 字符上限致 `DNN-based_source_separation` 克隆后文件全丢 |

### 2.3 目录骨架

按「模型 / 数据 / 产物 / 报告 / 脚本」五分离建立：

```
01_models/   模型：代码与权重（零拷贝联接）
02_databases/ 数据集（只读）
03_outputs/  逐模型推理产物
04_reports/  交付物（按板块分）
tools/       全部脚本
```

### 2.4 数据集

| 数据集 | 内容 | 规模 | 用途 |
|---|---|---|---|
| **MUSDB18-HQ** | `mixture + vocals/drums/bass/other`，44.1 kHz 立体声 WAV | train 100 首 / test 50 首（≈30 GB） | 板 1 全部分离实验 |
| **DNS-Challenge 子集** | clean 语音 + noise + dev_testset + RIR | **77,210 wav / 4.17 GB**（5 个官方分片） | 板 2 降噪实验 |

> DNS 全量约 892 GB（单机不可行），故按「降噪实验最小可用集」挑了 5 个官方分片，
> 含**唯一带 reference 的官方测试集** `dev_testset_000`（921 条）。
> 评测口径写死：**museval BSS-Eval v4、中位数、基线 = mixture、跨数据集只比 ΔSDR**；
> 选片段用 `_scan_balanced_clip.py`（按 4 个 stem 能量占比最小值筛），避开低频引子陷阱。

## 5. 结论与坑

- ✅ 环境可复用、GPU 可用、数据集齐备、依赖已锁。
- 🔴 **坑 1**：系统 python 无 numpy → 所有子进程必须显式用 venv 解释器。
- 🔴 **坑 2**：`core.longpaths=true` 不设会**静默丢文件**（克隆后目录看起来在、文件全没）。
- 🔴 **坑 3**：SAC（Smart App Control）会拦截某些原生扩展，且**拦截名单会变** → 每次先重跑探测（见技能 `sac-blocked-python`）。
- 🔴 **坑 4**：长任务不能用 `schtasks`（被安全策略黑名单）也不能 `nohup &`（会话结束被硬杀）→ 只能前台跑或按规定后台方式。
