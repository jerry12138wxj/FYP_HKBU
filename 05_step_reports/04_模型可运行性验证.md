# 步骤 04 · 模型可运行性验证

> 一句话：逐个模型**真跑通一次前向并落盘**，回答「是否本地运行成功、效率如何、输出什么」。
> 对应计划阶段：**阶段 0 总闸门 + 阶段 1（T1.1–T1.4）** ｜ 交付汇报日期：2026-09-28

---

## 1. 这一步要什么

| 要解决的问题 | 验收标准 |
|---|---|
| 每个模型在本机真能跑 | 跑通一次前向并**落盘音频** |
| 成功判定**不可被假象欺骗** | **只看结果 JSON 的 `status`**，不看目录存在、不看返回码 |
| 效率可量化 | 有 RTF（实时因子）与墙钟时间 |
| 输出可追溯 | 每模型产物进独立文件夹 |

> 🔴 **本项目踩过「假 PASS」**（脚本内捕异常仍 0 退出），因此成功判定写死：**只认结果 JSON 的 `status=PASS`**。

## 2. 做了什么

### 2.1 板 1 · 统一基准跑通

- 入口：`tools/benchmark_model_universal.py`（统一加载器 `REGISTRY`，不重写加载链路，防口径分裂）。
- 方式：**每模型一子进程**（8 GiB 显存，同进程多模型会 OOM）。
- 结果：**MUSDB18 test 集 563 个推理任务 PASS**，逐模型落盘 4-stem / 单目标音频。

### 2.2 板 2 · 阶段 0 门禁

- 门禁 = **加载 + 前向 + 探针**三合一，7 个板 2 条目**全 PASS**（见 §4 门禁表）。
- 探针用「真实 noisy/clean 对 + SI-SDR 改善」证明模型**真的降了噪**（不是输出 ~0 的退化解）。

### 2.3 部署完整性再核验

`tools/_verify_model_deployment.py` → **19/19 PASS**（模型卡 + code 联接 + 权重归属 + git 完整性 + 零拷贝）。

## 7. 结论与坑

- ✅ **全部模型在本机跑通**并落盘，效率已量化。
- 🔴 **坑 1（假 PASS）**：脚本内捕异常仍返回 0 → **只看 JSON 的 `status`**，「有目录」≠ 成功。
- 🔴 **坑 2（CUDA sysmem fallback）**：超显存**不报 OOM**，悄悄进系统内存，步耗时暴涨 10~100×（DPRNN batch16：0.37 s → 27 s/步）→ 显存规划靠实测峰值。
- 🔴 **坑 3（半成品音频）**：FLAC `total_samples` 哨兵异常 → `soundfile` 报 `array is too big`；先 `sf.info()` 比对 frames。
- ✅ **坑 4（口径）**：DPRNN 是自训权重，SI-SDR 为负 → 只作**负面证据**，不参与排名。
