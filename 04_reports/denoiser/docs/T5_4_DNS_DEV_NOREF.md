# dns_dev 无参考评测（T5.4）

状态：⚠️ **本文的 v1 版本数字全部作废**（P19 采样率契约 bug 造成的假象），
当前为 P19 修复后的重跑结果。

## 0. 为什么单列一节

DNS `dev_testset/noisy_testclips` **只有 noisy、没有 clean GT**（官方盲测集）。
因此这里**不产出** SI-SDR / PESQ / STOI ——
只产出**无参考侧的输出统计**（`level_ratio`、`est_rms`、门控塌陷率）。

它的作用不是「给出指标」，而是回答一个 valentini 回答不了的问题：

> **denoiser 的输出电平压低，在官方盲测分布上的发生率有多高？**

valentini 片段只有 1.74 s；dns_dev 片段平均 **27.05 s**，
含大量真实远场、低电平、长静音成分 —— 是检验「电平行为是否与语音活动有关」的关键分布。

## 1. 口径与字段

| 项 | 值 |
|---|---|
| 采样率 | 主口径 16000 Hz（**必须走契约率中转**，见 P19） |
| 片段数 | 921（DNS dev_testset 全量） |
| 模型 | 5（mel_roformer ×2 + denoiser ×3） |
| `reference_mode` | **`noref`** |
| full-ref 列 | **`null`，不是 0** |
| 可报列 | `est_rms` / `in_rms` / `level_ratio` |

`level_ratio` = 输出 rms / 输入 noisy rms。**这不是指标，是行为描述量。**

## 2. 🔴 v1 版本为什么作废（P19）

v1 报告的数字（塌陷率 40.3% / 38.3% / 45.4%）**全部是管道假象**。

根因：denoiser 的 wrapper 内部写死 `convert_audio(wav, 44100, 16000, 1)`，
假定输入永远是 44.1 kHz；而 v1 的 `eval_one` 把**已经重采样到 16 kHz** 的信号直接喂入
→ 被降采样**两次** → 音频**加速 2.76 倍**、音高上移 → 远超训练分布 → 大量片段被判为非语音而压低。

| 口径 | 传入 wrapper | wrapper 输出 | 有效时长 |
|---|---|---|---|
| **16 kHz（bug 版）** | 88343 样本 | 32051 样本 | 2.00 s（真值 5.52 s） |
| 44.1 kHz | 243495 样本 | 88342 样本 | 5.52 s ✅ |

决定性证据：**同一个模型、同一批音频，44.1 kHz 口径下塌陷数为 0**。
模型行为不可能这样依赖评测口径。详见 `P19_SAMPLE_RATE_CONTRACT_BUG.md`。

修复分两发：
1. registry 暴露 `run.contract_sr`，eval 加双向 `resample_mono`；
2. 第一发修完引入了「`noisy` 被覆盖」的第二发 bug（`si_sdr_in` 出 −73 dB），
   改为 `noisy_in`（喂模型）/ `noisy`（算指标）分离 + 新增 SR-sanity 长度护栏。

## 3. P19 修复后的结果（重跑）

4335 cells（5 模型 × 867 条可比片段），**err = 0**。因无 GT，下表只有电平行为量。

### 3.1 电平行为量分布

> ⚠️ `dns_dev` 是 **noref** 集：`eval_one` 在无 GT 时提前返回，因此 manifest 里
> **没有 `level_ratio` 字段**。下表由 `est_rms / in_rms` 现算（数学上等价于 `level_ratio`）。

| 模型 | n | p05 | **中位** | p95 | < 0.05 | **< 0.20（会被判 skipped）** |
|---|---:|---:|---:|---:|---:|---:|
| mel_roformer_denoise | 867 | 0.8084 | **0.9945** | 1.0000 | 0 (0.0%) | **1 (0.1%)** |
| mel_roformer_denoise_aggr | 867 | 0.7834 | **0.9930** | 1.0007 | 0 (0.0%) | **3 (0.3%)** |
| denoiser_dns48 | 867 | 0.4017 | **0.8339** | 0.9794 | 2 (0.2%) | **9 (1.0%)** |
| denoiser_dns64 | 867 | 0.4131 | **0.8660** | 0.9960 | 0 (0.0%) | **9 (1.0%)** |
| denoiser_master64 | 867 | 0.3464 | **0.8329** | 0.9881 | 1 (0.1%) | **15 (1.7%)** |

> ⚠️ **n=867 而不是 921**：54 条片段时长超过 `MAX_CLIP_SEC = 30 s`（数据集最长一条 **77.5 s**，
> 而中位仅 18.6 s）。mel_roformer 是全序列 transformer，在 3416414 样本 × 2ch 输入上
> 触发 `CUDA driver error: device not ready`（**不是 OOM，是 CUDA 上下文崩**）。
> 为保证**所有模型看到同一批片段**（可比性优先于覆盖率），统一跳过超长片段，
> 并在 manifest 里显式记 `skipped: too_long(...)` 而不是崩掉。
> denoiser 因内部自动分块本可跑过，但为口径一致也一并跳过。

## 4. 判读（P19 后定稿）

### 4.1 核心数字：塌陷率从「40%」降到「1%」

| 模型 | v1（bug）< 0.20 | **P19 后 < 0.20** | 倍数 |
|---|---:|---:|---:|
| denoiser_dns48 | 40.3% | **1.0%** | **÷40** |
| denoiser_dns64 | 38.3% | **1.0%** | **÷38** |
| denoiser_master64 | 45.4% | **1.7%** | **÷27** |
| mel_roformer ×2 | 0.0% | **0.1% / 0.3%** | ≈不变 |

**v1 的「塌陷率」有约 97.5% 是 bug 造出来的。**

### 4.2 干净数据上的三点新结论

1. **denoiser 在官方盲测集上有真实的轻度电平压低**：
   `level_ratio` 中位 **0.833~0.866**（mel_roformer 是 0.993~0.995）。
   这比 valentini 上的 ~1.00 明显 —— **长片段确实触发更强的增益压缩**。
   ★ 这正是 v1 想要的结论，但量级完全不同：是「压低 15%」而不是「整段静音」。

2. **门禁 `LEVEL_GATE=0.20` 几乎不触发**（1.0~1.7%，即 9~15 条 / 867）。
   它保留下来是正确的（这些是真塌陷，剔掉比污染中位数好），
   但它**不再是一个「大面积失效模式」的证据**。

3. **v1 的「master64 门控最激进」方向恰好是对的，但幅度差 27 倍**：
   master64 仍是三者中 `level_ratio` 最低（中位 0.8329）、剔除最多（1.7%）。
   这个排序在干净数据上**存活**，只是不能支撑「45.4% 失效」那样的叙事。

> 🔴 **诚实记录**：v1 用这里的数字论证了「master64 的塌陷更极端，只是恰好较少触发」，
> 并写进了 `T5_DENOISE_STRATIFIED.md` §3。修复后**方向存活、幅度作废**。
> 报告须用本节新数字，不得引用 40.3/38.3/45.4%。

### 4.3 与 valentini 的对照（P19 后）

| 模型 | valentini 中位 `level_ratio` | **dns_dev 中位** | 说明 |
|---|---:|---:|---|
| denoiser_dns48 | 0.9995 | **0.8339** | 长片段压低更明显 |
| denoiser_dns64 | 1.0088 | **0.8660** | 同上 |
| denoiser_master64 | 1.0002 | **0.8329** | 同上 |
| mel_roformer_denoise | 0.9995 | **0.9945** | 几乎不动 |

→ **「片段越长、denoiser 的电平压低越多」这一趋势成立**（valentini 1.74 s ≈ 1.00；
dns_dev 中位 18.6 s ≈ 0.83~0.87）。

> ⚠️ **一句重要限定**：valentini 的 `level_ratio` 是 16 kHz 口径下的
> **修复后**数值（中位 ~1.00）。这与 `denoise_sr_bug_audit.json` 里 150 条子集
> 的 0.9466 略有差异 —— 后者是**未重跑前**的审计子集，且 `level_ratio` 与
> 「是否被门禁截断」有关。**报告引用时以全量 824 条的中位 ~1.00 为准**，
> 并注明 valentini 上 denoiser 的电平压缩在整体中位上不显著、
> 只在 dns_dev 的长片段上才明确显现。

## 5. 对报告的约束

1. **dns_dev 行不得出现 SI-SDR / PESQ / STOI 的任何数字**，这些列写 `null`。
2. 该表**标题必须写明"无参考（盲测集）"**，避免读者误当作指标表。
3. `level_ratio` **不是质量指标**，是行为描述量；措辞用「电平比」而非「降噪效果」。
4. **任何跨数据集比较必须先确认两边都走契约率**（P19 连带纪律）。
5. 论文中这张表的位置：放在 valentini 主表**之后**，作为「模型行为在第三方分布上是否重现」的验证。
6. 🔴 **不得引用 v1 的 40.3/38.3/45.4%**，也不得引用「master64 门控最激进」的**幅度**论证。

## 6. 复现

```bash
cd tools
PYTHONPATH=. <venv>/python.exe -X utf8 _denoise_eval.py run \
    --models A,B --dataset dns_dev --sr 16000 --allow-noref --resume
PYTHONPATH=. <venv>/python.exe -X utf8 _denoise_eval.py resummary
```

⚠️ **`--allow-noref` 是必需的**（该集无 GT），漏掉会直接报错退出。

耗时：dns_dev 全量 **约 55 min**（5 × 921 cells）。
其中 **mel 族约 39 min/模型**（27 s 长片段 + 44.1k 契约率重采样），
denoiser 约 3~4.5 min/模型。**比 v1 估计的 30 min 长很多** ——
v1 的 30 min 是在 bug 路径上跑的（音频被压缩到 1/2.76 倍时长，自然快）。
