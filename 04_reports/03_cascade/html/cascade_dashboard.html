1实验设计：为什么必须有「只付代价、不做动作」的对照臂

问句：把语音降噪器接在音乐源分离的前/后，SDR 是涨还是跌？关键陷阱：denoiser 的契约是 44.1k→16k→mono→44.1k，即使网络换成恒等，信号也已被限带到 8 kHz + 下混单声道（音乐高频大量在 8 kHz 以上）。没有对照臂，任何涨跌都无法排除「其实是带宽被砍」。

链路含义
L0noisy mixture -> SEP（基线）
L1noisy mixture -> denoiser -> SEP
L1bnoisy mixture -> 仅16k/mono往返(不降噪) -> SEP（★对照：纯代价）
L1mnoisy mixture -> mel_roformer -> SEP（★对照臂：无带宽代价）
L2noisy mixture -> SEP -> 对 vocals 降噪
L2bnoisy mixture -> SEP -> 对 vocals 仅限带（★对照）
L3noisy mixture -> denoiser -> SEP -> 对 vocals 降噪
前置变体含义
Vdry干 mixture（无噪声）——**锚点**，用于校验 loader/口径未漂移
V0带噪 mixture（L0 基线输入）
V1den带噪 mixture -> denoiser 降噪（L1/L3 输入）
V1mel带噪 mixture -> mel_roformer 降噪（L1m 输入，★对照臂）
V1bl带噪 mixture -> **仅 16k/mono 往返、不降噪**（L1b 输入，★对照）
★ 恒等式（逐格严格成立）：L1 = L1b(带宽代价) + (L1−L1b)(降噪净动作)。L1m（mel 前置）与 L1b 是两条「只付代价」的对照臂：L1b 换恒等网络、L1m 换近恒等的 Mel-RoFormer。若 L1m ≈ L1b，则进一步证明伤害来自「降噪动作」而非管线固定损耗。

5诚实性检查（T6.4 · R12 / P7）

  • Δ 为负即负，不挑数据。本实验整体是一个负结果：语音降噪器接在音乐源分离前置 → avg4 SDR 净跌约 -4.0 dB，其中 80% 来自「降噪」动作本身。
  • 不预设降噪有用（P7）：P17 只预测「动作量可迁移」，动作可以是负的 —— 本实验正是负的，照报。
  • 先判噪声类型（P17）：本集噪声按波峰因子判为瞬态型（缩放后中位 16.3），与 T5.4 synth 同族，故 P17 预测可迁移。⚠️ 不能用 hf_ratio 当噪声类型判据（那是比例量，音乐自带大量高频）。
  • 锚点不成立则整张矩阵作废：40 个干档锚点 Vdry 全部 PASS，avg4（demucs 9.040 / mdx 9.910 / bsrnn_all 9.297 / umx 5.375）与历史整曲扫描（9.05 / 9.87 / 5.49）吻合 → loader/GT/museval 口径未漂移。
  • 门禁语义修正后重判：级联里「输出相对输入的量级」就是被测现象本身（前置把 drums 压到 0.006 是发现不是故障），旧判据误判 35 格 FAIL 并让整列从矩阵里静默消失；改为「输入没写坏 且 输出非全零/NaN」后 680/680 PASS。

6引用前必读：口径与已知坑

  • 32-bit float WAV：噪声脉冲性强（缩放后波峰因子 max 很大），按功率匹配 SNR 后 noisy 峰值冲高 → 写 PCM_16 会静默削波 30/40 格。⚠️ 峰值大不伤模型：分离 wrapper 内部按输入自身 mean/std 归一化再还原。
  • G2 门禁：拿 float32 存储值比 float64 精确和 → 纯量化（0.55 ulp）会被误判 FAIL。正确判据 = float32 重建逐位相同。
  • 片段：20 s 片段（非整曲），与 T4/T5 口径一致、匹配 museval 2 s 窗。
  • 偏离记录：计划书写的「BSRNN-opt」实为人声单轨（违反 R10）→ 改用 bsrnn_all（oBSRNN 4 ckpt 四轨）。
  • 无法创建脱离进程：本沙箱 nohup & / cmd start 被拒，后台任务随会话结束被杀 → 主跑改用逐格 JSONL 增量落盘 + resume，中断可幂等续跑。
