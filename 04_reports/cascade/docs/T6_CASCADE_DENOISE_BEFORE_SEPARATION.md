## 0. 一句话

把**语音**降噪器接到**音乐**源分离上，SDR 是涨还是跌 —— 以及涨跌里有多少是**降噪的净动作**、
有多少只是**前置管线固有的带宽代价**。后者靠一条「只付代价、不做动作」的对照链路（L1b）减出来。

### 结论：**跌**，而且伤害主要不是带宽代价，是降噪动作本身

| 量 | 中位 ΔSDR（跨 4 模型 × 4 SNR 档，n=16） | 占 L1 的比例 |
|---|---:|---:|
| **L1** 前置降噪（denoiser，全代价） | **−3.993 dB** | 100% |
| **L1b** 仅 16k/单声道往返（★只付代价、不做动作） | **−0.894 dB** | 22% |
| **净降噪动作 = L1 − L1b** | **−3.214 dB** | **80%** |

→ 把**语音**降噪器接到**音乐**源分离**之前**，avg4 SDR **净跌约 4 dB**；
其中 **80% 来自「降噪」这个动作本身**，只有 22% 是前置管线固有的带宽/单声道代价
（两者之和 −4.108 vs L1 的 −3.993，差 **0.12 dB** 纯因中位数不可加，见 §7.4）。
**这是一个负结果，照报（R12 / P7）。**

两条对照链路把「涨跌」拆干净了：

- **L1b**（逐行镜像 wrapper、模型换恒等）＝ **−0.89 dB** → 带宽代价真实存在但**不是主因**；
- **L1m**（mel_roformer，另一模型族、原生 44.1 kHz、**无带宽代价**）＝ **−0.24 dB** → 近恒等，几乎不动。

**后置**降噪则近乎中性：**L2 = −0.060 dB**（其对照 L2b = −0.092 dB → **净后置动作 +0.034 dB**）；
**L3（前置+后置）= −4.012 dB ≈ L1** —— 后置环节既救不回前置造成的损失，也不额外加伤。

**方向性规律**：输入越干净，跌得越狠（−5 dB 档 −1.4 ~ −3.9 dB；**+10 dB 档 −3.4 ~ −7.8 dB**）。
**机理**：denoiser 把音乐里的 **drums / bass / other 当成噪声压掉**（输出电平掉到输入的 0.6%~6%，
而 vocals 顶到 98%~100%）→ 对「分离」这个任务而言，等于**把待分离的混合结构提前摧毁**。
这是**任务错配**，不是实现错误（契约率链已走通、L1b 逐行镜像，见 §3 / §7）。

## 1. 为什么必须有对照链路（设计要点）

只说「加了降噪器之后 SDR 变了 X dB」是**不可归因**的。denoiser 的内部契约是
`44.1 kHz 立体声 → 16 kHz 单声道 → [模型] → 升回 44.1 kHz`（P19 契约率链）。
也就是说，即便把中间的神经网络换成一个恒等函数，信号也已经**被限带到 8 kHz、被下混成单声道**了。
音乐里的镲片、齿音、空间感大量存在于 8 kHz 以上 —— 这个代价必须单独量出来。

于是本实验设 **7 条链路**，其中 3 条是对照：

| 链路 | 定义 | 作用 |
|---|---|---|
| **L0** | 带噪 mixture → SEP | **基线**（不降噪）。所有 Δ 都以它为 0 点 |
| **L1** | 带噪 mixture → **denoiser** → SEP | 前置降噪（全代价 + 真动作） |
| **L1b** | 带噪 mixture → **仅 16k/单声道往返、不降噪** → SEP | ★对照：**纯带宽代价** |
| **L1m** | 带噪 mixture → **mel_roformer** → SEP | ★对照臂：另一个模型族，**无带宽代价**（原生 44.1 kHz） |
| **L2** | 带噪 mixture → SEP → **对分离出的 vocals 降噪** | 后置降噪 |
| **L2b** | 带噪 mixture → SEP → **对 vocals 仅限带** | ★对照：后置的纯代价 |
| **L3** | 带噪 mixture → denoiser → SEP → 对 vocals 降噪 | 前置 + 后置 |

**关键恒等式**：`L1 = 带宽代价 + 降噪净动作 + 交互项`。
`L1b` 逐行镜像 denoiser 的 wrapper（同一个 `convert_audio` 下行、同一个 `torchaudio.resample` 上行），
**只把模型前向换成恒等** —— 所以 `L1 − L1b` 就是降噪的净效应。

> 这正是 **P19 的元教训**要求的对照纪律：「能解释一切的叙事，往往就是 bug 在说话」。
> 没有 L1b，任何 L1 的涨跌都无法排除「其实是带宽被砍了」。

| 门禁 | 条数 | 判据 | 结果 |
|---|---:|---|---|

**合计 90 条门禁，失败 0。**

### 3.1 两个被门禁挡下来的坑（都曾静默）

**(a) G2 阈值写错 → 把纯量化误判成 FAIL。**
`noisy` 以 float32 存储，若拿它去比 **float64** 的精确和，残差纯属量化
（实测 **0.55 ulp**，绝对值可达 **1.05e-6**），旧阈值 `1e-6` 必然 FAIL。
正确判据是 **float32 重建逐位相同**（实测 40/40 相同），float64 残差降级为信息量。

**(b) 定点写入会静默削波。**
按功率匹配 SNR 后，噪声池波峰因子 p95 = 53.8、实测最大 **81.5**，
`noisy` 峰值**中位 1.44 / 最大 18.07**（≈ +25 dBFS）。
若按最初的 `PCM_16` FLAC 写盘，**40 个 V0 里 30 个会被削波**（−5 dB 档最多削掉 0.77% 样本），
而脚本**完全不报错**。
→ 改为 **32-bit float WAV**（`subtype="FLOAT"`，与 T4 混响实验同一约定），精确无损。

> 📌 关于峰值 18 是否伤到分离模型：**不会**。四个分离 wrapper 都在内部按输入自身的
> `mean/std` 归一化、输出再还原（`wav=(wav−mean)/(std+1e-8)` → `out*std+mean`），
> 绝对电平被吸收。且 L0/L1/L1b/L1m 拿到的是**同一个**输入，电平不构成混淆。
> 此处保留「原始相加、不做归一化」是与项目既有分离管线一致的选择。

### 3.2 G5：噪声类型判定（P17 的**前提**必须当场验，不能外推）

| 量 | 值 |
|---|---|
| `hf_shift` 中位（noisy 相对干 mixture 的 hf_ratio 位移） | **−0.0017**（≈ 0） |
| 缩放后噪声**波峰因子**中位 / p95 | **16.3** / **53.8** |

**判定**：噪声**高度脉冲**（瞬态型）→ 与 T5.4 的 synth 集同族，
P17 对 denoiser 的「有效」预测**可迁移**到本集。

⚠️ **`hf_shift ≈ 0` 不是反证**。`hf_ratio` 是**比例量**（P18 / T5.6 已证）：
音乐本身自带大量高频（镲片/齿音），把加性噪声混进去，该比例几乎不动。
若拿它当主判据会得出「前提不成立」的错误结论。**主判据必须是噪声自身的脉冲性。**

⚠️ 这不等于「预设 denoiser 有用」：P17 只给出**动作量**的预测，而**动作可能是负的**
（把语音降噪器用在音乐上是域外使用）。变差照报（P6 / R12）。

### 3.3 门禁语义修正：旧判据把「被测现象」判成了 FAIL

首轮 680 格跑完后记录为 `n_sep_pass = 645`：**35 个 FAIL 全部集中在 V1den**（demucs 30 / mdx 5），
`reason` 一律是 `level out of band`。核对后确认**不是信号被写坏**，正是 §6.4 那个真实现象本身：

- 旧判据 `0.01 <= level <= 10.0` 假定「分离输出各轨电平应与输入同量级」；
  但 denoiser 前置后 drums 电平 = **0.0014**（demucs 样例格）—— 这是**发现**，不是故障；
- 更糟的是 `cmd_summary` 只统计 `status == PASS` 的记录 → 被误判的格**整列从矩阵里消失**，
  表现为「L1 偶尔是 None」这种**空洞**，而不是任何报警。

**修正**：正确判据 = ① 输入没被写坏（`mix_rms` 有限且非退化）② 输出**不是全零/ NaN**；
电平量级仍原样记录在 `gate.levels` 供分析。工具 `tools/_cascade_regate.py`
（**免重跑重判**，只改派生量 `status`，不动任何测量值），另保留旧判据为 `gate.band_ok` 审计字段。
重判后 **680/680 PASS**。

> 与本项目「静默错陷阱⑤」同源：**判据写歪不会报错，只会让数据悄悄消失。**

## 4. 前置变体的性质（独立复算，`_front/`）

对 40 格逐条复算「输出 rms / 输入 rms」：

| 变体 | 含义 | `level_ratio` 中位 | 范围 | 异常 |
|---|---|---:|---|---:|
| **V1bl** | 仅 16k/单声道往返，**不降噪** | **0.847** | 0.751 ~ 0.957 | 0 |
| **V1den** | denoiser 降噪 | **0.216** | 0.070 ~ 0.471 | 0 |
| **V1mel** | mel_roformer 降噪 | **0.851** | 0.672 ~ 0.960 | 0 |

三条读出来的东西：

1. **V1mel ≈ V1bl（0.851 vs 0.847）** —— mel_roformer 在这批噪声音乐上**几乎是恒等映射**，
   与 P19 存活清单的结论完全一致。
2. **V1den = 0.216（−13 dB）** —— denoiser 把总电平砍到 1/5。
   这不是缺陷而是**算出来的必然**：在 −5~10 dB SNR 下噪声占主导功率，
   而 denoiser 对噪声的抑制量极大（P19 实测纯噪声上 **32~41 dB**），
   压掉噪声 = 压掉大部分总能量。
3. 全部 120 条变体**格式/长度/电平 0 异常**（44.1 kHz / 2ch / 与 V0 逐样本同长）。
   ★ 长度对齐是必需的：`44.1k→16k→44.1k` 往返会差几个样本，
   不对齐会让 V1bl 与 V0 的 **museval 窗数不同** —— 等于偷偷换了评测口径。

   （基线贴地，Δ 相对解释力弱，见 §7）。
2. **输入越干净，降噪伤得越狠。** 净动作按 SNR 档的中位：
   `−5 dB → −0.635`｜`+0 dB → −3.208`｜`+5 dB → −4.872`｜`+10 dB → −6.087`（**单调恶化**）。
   与「低 SNR 时噪声本就占主导、压噪声相对有收益；高 SNR 时压掉的几乎都是音乐」一致。

   两者行为模式截然不同 → 从侧面确认 `L1 − L1b` 抽出来的确实是**降噪网络的行为**，
   而不是管线的固定损耗。

### 6.4 机理：denoiser 把伴奏当作噪声压掉

分离**输出**各轨 rms ÷ **输入** rms 的中位（40 格；`gate.levels`）：

| 模型 | 变体 | vocals | drums | bass | other |
|---|---|---:|---:|---:|---:|
| demucs | **V0**（基线） | 0.368 | 0.562 | 0.372 | 0.428 |
| demucs | V1bl（仅限带） | 0.414 | 0.518 | 0.444 | 0.372 |
| demucs | V1mel | 0.420 | 0.529 | 0.439 | 0.349 |
| demucs | **V1den** | **0.996** | **0.006** | **0.015** | **0.046** |
| mdx | **V1den** | **0.986** | **0.062** | **0.016** | **0.087** |
| bsrnn_all | **V1den** | **0.985** | **0.022** | **0.000** | **0.000** |
| umx | **V1den** | **0.981** | **0.048** | **0.021** | **0.064** |

- **V1bl / V1mel 与 V0 同量级**（0.29 ~ 0.53）→ 限带与 mel 前置**没有**改变分离器的行为；
- **V1den 一致性反转**：vocals 顶到 **≈1.0**、其余三轨塌到 **0.000 ~ 0.087**。
  即：预热后的输入在 denoiser 眼里**几乎只剩人声**，分离器于是退化为**恒等映射**
  （直接把输入当 vocals 输出）→ 这正是 ΔSDR 大跌的**直接机理**。
- bsrnn_all 的 bass/other 到 **0.0000 / 0.0001**，是四个模型里最彻底的。

## 7. 诚实性检查（T6.4，R12 / P7）

### 7.1 Δ 为负的格：**照报**（`_t6_verify.py` 只读 CSV 核出）

| 链路 | 负 Δ 格数 / 总 | 最负 | 非负格（全部列出） |
|---|---:|---:|---|
| **L1** 前置降噪 | **15 / 16** | −7.830 | `umx @ −5 dB` **+0.429** |
| **L1b** 仅带宽（对照） | 14 / 16 | −1.738 | `umx @ +0 dB` +0.041、`umx @ −5 dB` +0.077 |
| **L1m** mel 前置（对照） | 11 / 16 | −1.072 | umx@+10 +0.037、demucs@0 +0.168、mdx@0 **+0.510**、umx@0 +0.322、umx@−5 +0.438 |
| **L2** 后置降噪 | 10 / 16 | −0.672 | umx@+10 +0.154、bsrnn@+5 +0.189、umx@+5 +0.234、umx@0 +0.405、demucs@−5 **+0.647**、umx@−5 **+0.854** |
| **L2b** 后置限带（对照） | 13 / 16 | −0.302 | 全是 umx（+0.066 / +0.014 / +0.058） |
| **L3** 前置+后置 | **15 / 16** | −7.997 | `umx @ −5 dB` +0.419 |

三个前置变体合并：**40 / 48 格为负**。

**★ 全表没有任何一处出现「降噪带来大幅 SDR 增益」**：所有非负格都是**小幅**（最大 **+0.854 dB**，
且集中在 umx）。唯一系统性「好看」的档位是 **umx @ −5 dB**，但该档 L0 中位只有 **0.014 dB**
（基线贴地，Δ 的相对解释力很弱）——**不能**据此说「降噪在小 SNR 下有用」。

> 也就是说：**结论不是「有时有用、有时有害」，而是「几乎没有增益，且代价随输入变干净而放大」。**

### 7.2 域外泛化：这是**任务错配**，不是实现错误

denoiser 是**人声/语音**降噪器（DNS 训练目标里的「噪声」= 环境噪声 / 混响）。
音乐里 drums / bass / other 在它的判据下**与噪声不可分**：V1den 下三轨电平塌到输入的
**0.0000 ~ 0.087**、vocals 顶到 **≈ 1.0**（§6.4）。它实际做的是「**保留人声、抹掉其余**」——
对**源分离**而言，这恰好是**提前摧毁待分离的混合结构**。

排除「是我们实现错了」的依据（三层）：

1. **契约率链已走通**（P19 修法：显式读 `contract_sr`、绝不原地覆盖、加长度护栏）。
2. **`L1b` 逐行镜像同一 wrapper、只把模型前向换成恒等** → 把纯管线代价（−0.89）与网络净动作（−3.21）干净分开。
3. **`L1m`（mel_roformer）走同一条链但绕过 16 k 瓶颈** → 近中性（−0.24），说明链路本身没有系统性破坏。

### 7.3 与 P17 的关系：**动作量大 ≠ 有益**

G5 已**当场**验证本集噪声是**瞬态型**（波峰因子中位 16.3，与 T5.4 synth 同族），
P17 预测 denoiser 在此有效域内**动作量最大** —— 实测它确实是四个模型里跌得最深的（−3.9 ~ −7.8 dB）。
**但方向是负的。** 这正好印证 P17 的适用边界：它只预测**动作量**、**不预测符号**；
把「动作量大」读成「有益」属于**误用**。

### 7.4 边界与不主张

- **覆盖范围**：MUSDB test Top-10 曲 × 20 s 窗 × 4 SNR 档 × 4 个四轨模型。
  **不主张**外推到整曲、其它曲库、其它降噪器或其它噪声类型。
- **后置链路（L2/L3）的单轨 Δ 被稀释 4 倍**：后置只改 vocals，其余 3 轨沿用基线，而 `avg4` 是 4 轨均值
  → 单轨 Δ ≈ **4 × avg4 Δ**。故 L2 = −0.060 dB 换算到 vocals 单轨约 **−0.24 dB**。
  结论不变（仍不值得做），但**不能**把 −0.060 直接读成「后置无损」。
- **分解是逐格精确的，不是拟合**：`L1 = L1b + (L1 − L1b)` 对**每一格**恒等成立（`L1b` 与 `L1` 用同一输入、
  同一版 wrapper）。§6.1 里 −0.894 + (−3.214) = −4.108 与 L1 的 −3.993 差 **0.12 dB**，
  纯粹因为**中位数不可加**，**不是**存在额外的「交互项」。
- **未验项**：`sum_stems_eq_mixture`（G3）只验了**干** mixture（10/10 PASS）；
  带噪 mixture 的加性由 G2「float32 重建逐位相同」保证。

## 8. 可复现命令

```bash
# 1) 计划（纯 CPU）
python tools/_cascade_experiment.py plan

# 2) 合成带噪集 + 门禁（纯 CPU）
python tools/_cascade_experiment.py make-noisy

# 3) 前置变体
python tools/_cascade_experiment.py prep --op vbl        # L1b 输入（仅限带）
python tools/_cascade_experiment.py prep --op vden       # L1/L3 输入（denoiser）
python tools/_cascade_experiment.py prep --op vden-mel   # L1m 输入（mel_roformer）

# 4) 分离推理（每模型一个子进程，避开同进程多模型 OOM）
#    --resume：幂等跳过 cascade_eval.partial.jsonl 里已完成的格（长任务被中断后直接重跑）
python tools/_cascade_experiment.py run --models demucs,mdx,bsrnn_all,umx \
       --variants V0,V1den,V1bl,V1mel --resume

# 4b) 门禁语义重判（免重跑；只改派生量 status，不动测量值）
python tools/_cascade_regate.py            # 只报告
python tools/_cascade_regate.py --apply    # 写回

# 5) 后置处理与重算
python tools/_cascade_experiment.py prep-post --op vbl --models demucs,mdx,bsrnn_all,umx
python tools/_cascade_experiment.py prep-post --op vden --models demucs,mdx,bsrnn_all,umx
python tools/_cascade_experiment.py post --models demucs,mdx,bsrnn_all,umx

# 6) 汇总 + 出图
python tools/_cascade_experiment.py summary
python tools/_plot_cascade.py
```

每行 CSV 都带 `reproduce_cmd` 字段（计划书 D8 要求「每格标可复现命令」）。
