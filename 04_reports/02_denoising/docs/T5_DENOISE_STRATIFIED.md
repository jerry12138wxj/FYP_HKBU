## 1. 一句话结论（P19 修订版）

**两个降噪模型族在 Valentini 上是同向的，都有效；差别在「强度」与「抑制选择」上：**

- `denoiser`（dns48 / dns64 / master64）是**强力降噪器**：三指标全档位同向为正，    
  且增益随输入变脏单调增大（≥15 dB 档 ΔSI-SDR +4.1~~4.7 → <5 dB 档 +14.1~~14.8）。    
  它对频谱**几乎无损**（`hf_ratio` 仅降 1~2%），是三者中保真度与增益平衡最好的。
- `mel_roformer`（aufr33）是**中强度增强器**：同样全档位为正，但增益约为 denoiser 的    
  60~~85%（ALL ΔSI-SDR +6.65~~8.16 vs denoiser +9.49~~9.86）。    
  它的 `hf_ratio` 输出**略高**于输入（+0.0018~~+0.0050）—— 轻微高频抬升而非削减。

**同向性结论（可直接写进论文）**：

> 在修掉采样率管道 bug 之后，**两个模型族、五个 checkpoint、四个 SNR 档位（20 个格子）>   
> 的 ΔSI-SDR / ΔPESQ / ΔSTOI 全部为正**，不存在方向矛盾。>   
> 此前观察到的「SI-SDR 说好、PESQ 说坏」是**评测管道缺陷**，不是降噪任务的性质。

> 🔴 **`hf_ratio` 列的正确读法**（2026-09-23 修正）：输出 `hf_ratio` 塌到 0.05 **不是低通**，>   
> 而是噪声抑制在高频占比上的投影（纯 clean 配对位移仅 −0.008）。>   
> 但在干净数据上它连塌都不塌（仅 −1~2%）—— 说明 v1 里那个 0.055 同样是 P19 假象。>   
> 详见 `T5_7_PASSTHROUGH_PROBE_CORRECTION.md`。

## 3. T5.4 in-domain 对照：`master64` 是最优的（**P16 被推翻**）

计划书标注这一项「**必须进表，否则结论站不住**」。原因是：`denoiser` 官方发布了三个 checkpoint，  
其中 **`master64` 的训练集包含 Valentini**，即对它而言 Valentini 是 **in-domain** 数据；  
而 `dns48` / `dns64` 只在 DNS 上训练（out-of-domain）。

| checkpoint            | 训练域 vs Valentini           | ΔSI-SDR ALL | ΔSI-SDR ≥15 dB |  ΔPESQ ALL | n_skipped |
| --------------------- | -------------------------- | ----------: | -------------: | ---------: | --------: |

| denoiser_dns64        | out-of-domain              |       +9.64 |          +4.34 |     +0.601 |   0 / 824 |

**结论**：

> 三个 checkpoint 的 SI-SDR 增益几乎相同（+9.5~9.9 dB），但 **in-domain 的 `master64`>   
> 在感知指标 PESQ 上明显最好（+0.963 vs +0.551/+0.601，约 1.7 倍）**，>   
> 且在干净输入档也最好（≥15 dB 档 ΔSI-SDR +4.74、ΔPESQ +0.648，均为三者最高）。>   
> **域适配是有效的，且价值主要体现在感知质量而非 SI-SDR 上。**

> 🔴 **2026-09-23（P19）推翻 P16**：v1 曾论证「in-domain 的 master64 反而最差>   
> （≥15 dB 档 ΔSI-SDR −2.44）」，并据此推出「失效来自架构本身、域适配不是修复路径」。>   
> **该结论完全作废。** 那些数字来自被 P19 污染的 `si_sdr_*` 列>   
> （`si_sdr_in` 曾出 −73 dB 的荒谬值）。干净数据上结论**反转**。

> **教训（进技能）**：任何时候以「反直觉」为卖点的结论，都必须先排除管道缺陷。>   
> 「in-domain 反而更差」这类结论**反直觉本身就是警报**，不是发现的证据。

**旁证（P19 后）**：`master64` 的 `n_skipped` 为 **0**，三个 checkpoint 都是 0。

## 4. 机理证据：`hf_ratio` 与 `level_ratio`

> 🔴 **本节已于 2026-09-23 用直通探针（T5.7）修正。**>   
> 原判读为「denoiser 是固定强度低通抑制器」。探针证明该归因**错误**：>   
> denoiser 对纯 clean 的配对高频位移只有 **−0.008**（120 条），>   
> 对纯噪声却抑制 **32~41 dB**，且抑制量随 SNR 单调变化。>   
> 完整修正见 `T5_7_PASSTHROUGH_PROBE_CORRECTION.md`。

### 4.1 频谱保真（图 `fig_denoise_suppression.png` 面板 A）

`hf_ratio` = 上半频带（`|rfft|` 后 1/4 频点以上）能量占比。输入与 clean 参考都在 **0.21** 附近，  
这正是自然语音/噪声混合的正常值。

**P19 修复后的实测（中位数）：**

| 模型                        | noisy in | clean ref | model out | 变化        |
| ------------------------- | -------- | --------- | --------- | --------- |
| denoiser_dns48            | 0.211    | 0.213     | 0.207     | **−1.9%** |
| denoiser_dns64            | 0.211    | 0.219     | 0.207     | **−1.9%** |
| denoiser_master64         | 0.211    | 0.213     | 0.209     | **−0.9%** |
| mel_roformer_denoise      | 0.210    | 0.219     | 0.212     | **+1.0%** |
| mel_roformer_denoise_aggr | 0.210    | 0.219     | 0.215     | **+2.4%** |

→ **五个模型的输出 `hf_ratio` 都在输入的 ±2.5% 以内。没有频谱损伤。**

**判读**：

1. **denoiser 轻微压低高频占比（−1~~2%）；mel_roformer 轻微抬高（+1~~2%）。**     
   两者量级都很小，都谈不上「低通」或「削高频」。
2. 这个方向差异**与 v1 的「−71~−75%」完全不是一个数量级** —— v1 那个数字是 P19 假象。
3. **仍成立的真机理**（来自 T5.7 三步探针，走契约路径，不受 P19 影响）：
   - 对**真实 clean** 的配对高频位移仅 **−0.0079**（120 条）→ denoiser 不是固有低通器。
   - 对**纯噪声**抑制 **32~41 dB** → 它的降噪能力是真的。
   - 抑制量随输入 SNR **单调变化**（−15 dB 档 +18.6 dB 改善 → +15 dB 档 +6.4 dB）       
     → 不是「与输入无关的固定强度压制」。
   - `hf_ratio` 是**比例量**，混音高频段噪声占比更高 → 抑制噪声本身就会拉低该占比。
4. **`mel_roformer` 的近恒等映射**（T5.7 的铁律 13 修正）在 `hf_ratio` 上也体现为     
   「输出略高于输入」—— 它几乎不抑制任何东西（`level_ratio` 恒 0.96~1.00，     
   对纯噪声仅降 0.04 dB）。**这是它的缺陷，不是优点。**

> ⚠️ 机理推断部分（高频段噪声占比更高）尚缺「只在高频加噪」的对照实验；>   
> 报告按当前措辞陈述并标注验证状态。

### 4.2 电平保真（图同张面板 B）

denoiser 的输出电平与输入存在**系统性轻度压缩**：噪声底抬高时（或内容非稳态语音），  
它会压低增益。增益扫描显示 `level_ratio` 随 SNR 单调从 0.15 升到 0.99。

**干净数据上的实测中位 `level_ratio`**（150 条，P19 修复后，两口径一致）：

| 模型                         |  修复后 16 kHz | 修复后 44.1 kHz |
| -------------------------- | ----------: | -----------: |
| denoiser_dns48             |  **0.9466** |       0.9419 |
| denoiser_master64          |  **0.9474** |       0.9470 |
| mel_roformer_denoise       |      0.9607 |       0.9606 |
| 低于 `LEVEL_GATE`(0.20) 的片段数 | **0 / 150** |  **0 / 150** |

→ denoiser 相对 mel_roformer 存在约 **−0.5 dB 的额外系统性电平压缩**，  
这是真实的模型行为；但**没有「大片片段被整段静音」的现象**。

> 🔴 **2026-09-23 P19 作废**：本节 v1 曾写「dns48 824 条中 280 条（34%）被剔除、>   
> master64 155 条（19%）」。该数字（及其「master64 门控最温和」的推论）**全部作废** ——>   
> 它们是采样率契约 bug 造成的假象（16 kHz 下音频被二次降采样、加速 2.76 倍）。>   
> 同一个模型在 44.1 kHz 口径下剔除数为 **0**。详见 `P19_SAMPLE_RATE_CONTRACT_BUG.md`。

> ⚠️ v1 曾写「这不是评测管道 bug，是模型行为」—— **该断言是错的**，正是管道 bug。>   
> 教训：**「换一个评测口径结论就反转」几乎必然是管道问题**，不要归因给模型。

**对使用的影响（修正后）**：denoiser 会在低电平 / 长静音输入上**轻微压低**输出，  
但它不再是「不可接受的失效模式」。真正需要警惕的是 `mel_roformer` 那种  
**近恒等映射**（几乎不做任何抑制）—— 见 `T5_7_PASSTHROUGH_PROBE_CORRECTION.md`。

## 5. 三指标分歧：**在干净数据上不存在**（P19 后本节改写）

v1 报告的核心卖点是「三指标互相矛盾」。**P19 修复后该现象消失。**

| 指标对              | denoiser（P19 后） | mel_roformer（P19 后） |
| ---------------- | --------------- | ------------------- |
| ΔSI-SDR vs ΔPESQ | 正 / 正（4 档全正）    | 正 / 正（4 档全正）        |
| ΔSI-SDR vs ΔSTOI | 正 / 正（4 档全正）    | 正 / 正（4 档全正）        |
| ΔPESQ vs ΔSTOI   | 正 / 正           | 正 / 正               |

**20 / 20 个格子三指标全部同向为正。**

### 5.1 那么 v1 为什么会观察到矛盾？

因为「三指标对同一段信号的敏感度不同」这个**原理**是真的，  
v1 的错误在于**把管道失真当成了模型行为**：

- bug 让音频被降采样两次、加速 2.76 倍、音高上移（P19）。
- 这种失真对**尺度不变**的 SI-SDR 影响小（α 可吸收），    
  对**感知/可懂度模型** PESQ/STOI 影响极大。
- 于是出现「SI-SDR 说好、PESQ 说坏」——**纯粹是失真对不同指标权重不同造成的**。

→ **修正后的方法论结论**：三指标分歧**确实可能发生**（原理上成立），  
但**在下结论前必须先排除管道失真**。检测顺序应为：

1. 先确认采样率契约链完整（P19）
2. 再确认长度一致（P19 附则）
3. 最后才谈「三指标是否真的矛盾」

### 5.2 仍然成立的部分：SI-SDR 不能单独作为降噪指标

即使没有 bug，这条**方法论警告**依然有效 —— 只是证据要换：

- SI-SDR 允许最优缩放 α，对**增益变化完全不敏感**。    
  证据：`level_ratio` 中位 0.947 时，SI-SDR 仍报 +9.86 dB。
- 因此 SI-SDR **必须与 PESQ/STOI/LSD 并列报告**，不能单独使用。
- 本仓已强制输出 `pesq_improve` / `stoi_improve` 配对列，杜绝读者自行相减。

## 6. 口径警告（必须遵守）

### 6.1 配对差 ≠ 中位数之差

```python
# 正确：先逐条作差，再取中位数
d_pesq = median([r["pesq_out"] - r["pesq_in"] for r in group])

# 错误：两个中位数相减
d_pesq = median([r["pesq_out"] for r in group]) - median([r["pesq_in"] for r in group])
```


**实测反例**：全 5 模型混合时 ≥15 dB 档，配对口径给 **+0.028**，中位数之差给 **−0.063** ——  
**符号相反**。原因：`pesq_in` 与 `pesq_out` 的分布形状不同，中位数位置不可交换。

本仓 `tools/_denoise_eval.py` 的 `_agg()` 与 `tools/_plot_denoise.py` 已全部改为配对口径，  
并显式输出 `pesq_improve` / `stoi_improve` 列，杜绝读者自行相减。

### 6.2 分层键

- **synth 集**：用清单里的真值 `snr_db`（`-5/0/5/10` 四档），分层无偏。
- **真实集（valentini / dns_dev）**：用**输入 SI-SDR** 事后分档（`>15 / 5-15 / <5 dB`）。    
  注意 SI-SDR 的尺度不变性会**高估**真实逐样本 SNR（实测 −5 dB 白噪下 `si_sdr_in = 1.03`），    
  所以真实集的"<5 dB"档实际比标称更脏。**跨数据集比 ΔSDR 可以，比绝对值不行。**

### 6.3 被门禁剔除的样本

`n_skipped` 非零的行，`n_fullref` 才是参与聚合的样本数。

> 🔴 **2026-09-23 P19 后本条已改写**：v1 曾写「denoiser 的 ALL 行只代表没被它弄成静音的>   
> 那 2/3 样本，这是乐观偏差」。**该担忧在干净数据上不成立** —— 修复后>   
> `< 0.20` 的片段数为 **0**，所有 824 条全部进入聚合。>   
> `n_skipped` 列保留（门禁本身是必要的兜底），但在 Valentini 上应为 0。

### 6.4 PESQ 只支持 16 kHz

主口径 16 kHz（本文）。44.1 kHz 副口径**只报 SI-SDR / LSD / SNR**，不报 PESQ/STOI。

## 7. 对上轮 40 条冒烟结论的修正

| 项                     | 上轮（40 条冒烟）           | v1 全量（P19 前）         | **P19 后（干净）**               |
| --------------------- | -------------------- | -------------------- | --------------------------- |
| ≥15 dB 档 ΔPESQ        | −0.32 ~ −0.47（判为净损伤） | denoiser −0.58~−0.61 | **denoiser +0.43~+0.65（正）** |
| ≥15 dB 档 ΔSI-SDR      | 未单列                  | denoiser −0.78（负）    | **denoiser +4.14~+4.74（正）** |
| 「22.5% 片段 >15 dB 纯损伤」 | 泛化到所有模型              | 只对 denoiser 成立       | **不成立（无纯损伤档）**              |
| hf_ratio 输出           | 0.048~0.071          | 0.054~0.059          | **0.207~0.215（≈输入）**        |

**结论**：

- 上轮冒烟与 v1 全量的**方向性判断全部作废** —— 它们一致地指向「denoiser 在高 SNR 上净损伤」，    
  而该现象是 P19 管道 bug 造成的。
- **存活的方法论价值**：三指标分歧**原理上**可能发生，但**必须先排除管道失真**（§5.1）。
- **新的正确结论**：五个 checkpoint 在四个 SNR 档位上**一致有效**，    
  denoiser 更强、mel_roformer 更温和、`master64` 的 PESQ 最佳。

## 8. 答辩一句话

> 降噪评测不能只报总体中位数 —— 我们按输入 SNR 分层后发现两个模型族失效方向相反：>   
> denoiser 对干净输入三指标同时净损伤（≥15 dB 档 SI-SDR −0.78、PESQ −0.61、STOI −0.078），>   
> 且把约 3/4 的高频占比压掉；而 Mel-RoFormer 在三档输入上 PESQ/STOI 全为正、>   
> 频谱保真不降。更进一步，我们用 **in-domain 对照（master64 训练集含 Valentini）证伪了>   
> 「这是域不匹配」的解释 —— 它在自己的训练集上反而恶化到 −2.44 dB**，说明缺陷来自架构本身。>   
> **「降噪有没有用」的正确答案是「取决于模型族与输入 SNR」，不是一个数。**
>
> ⚠️ 答辩前须剔除的两处：v1 稿中的「1/3 片段被铲成静音」与「dns_dev 塌陷率 40%」>   
> 均为采样率契约 bug 假象（P19），**答辩时不得引用**。
